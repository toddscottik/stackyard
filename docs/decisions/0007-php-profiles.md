# PHP profiles and the Stage 8A boundary

Status: accepted for the initial Stage 8A implementation, 4 November 2026.

The existing installer, selections, dependency executor and process supervisor remain the single architecture. PHP is a runtime; a versioned Composer PHAR is a separate tool, always run by selected PHP. Composer install preserves its lockfile semantics; add/remove/selected-update use Composer, and successful mutations run `check-platform-reqs`. Home/cache live under app-owned project state; `COMPOSER_AUTH` remains an environment-based credential mechanism. Global Composer plugins/configuration are not imported automatically.

Extensions have immutable artifact identity and separate project activation. An isolated ini and empty scan directory are generated in an immutable revision, checked by an actual selected-PHP load probe, then activated through one atomic pointer. An OS file lock releases on crashes. Failed candidates keep the active profile. PHP patch switches require matching minor/API/build identity and another real load probe; build/minor mismatches are refused. Cleanup protects active profile artifact roots as well as package selections. Existing installations are referenced and never edited.

CLI, engine protocol and Tauri adapters share these services. An unconfigured project runs with `-n`. Project ini override arguments are refused; profile changes currently require a stopped project. Automatic restart of only affected PHP workers remains pending. A PHP HTTP development service can use the existing Apache proxy topology. This is not an Apache FastCGI/document-root provider and does not establish PHP `.htaccess` support.

Native Windows acceptance exposed an existing engine-autostart handle leak: replacing standard streams did not prevent other inheritable shell pipes reaching the background engine. The Windows adapter now uses explicit `CreateProcessW` with handle inheritance disabled, the same no-window flag and user environment, and tested UTF-16 argument quoting. It does not use job breakaway flags or change project-process ownership. A captured subprocess regression fails against the original implementation and passes with the engine still alive after the client/pipeline exits.

Only Windows PHP 8.5.12-1 and Composer 2.11.1 have approved new artifact pins. The native-extension catalog is deliberately empty until publisher digests and ABI/dependency metadata are verified. It defines the same download/install boundary and never synthesizes a pin. Memcached endpoints are separate from extensions; a bounded probe reserves a unique temporary key, verifies a roundtrip and cleans only its key. The unofficial Windows server candidate failed occupied-port behavior and is excluded. A PHP memcached load/set-get and managed server are still open acceptance gates.

No Mac is available in this session (confirmed by the user). Prior Node/Python Mac evidence remains valid for its original scope; PHP, native extensions, Memcached and integrated Mac acceptance remain pending. This decision records a partial stage, not a scope exclusion or release approval.
