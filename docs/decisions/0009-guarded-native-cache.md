# Guarded native Memcached and PHP extension provenance

Status: accepted, 4 November 2026. Extends the initial Stage 8A decision without adding a second launcher or installer.

The verified jefyt Memcached 1.6.8 Windows port accepts a private native Unix socket, but its direct TCP mode failed occupied-port refusal. The managed provider therefore never launches its TCP listener. It binds and holds a loopback engine listener first with Windows `SO_EXCLUSIVEADDRUSE`, then starts the native executable through the existing process/job owner using only a private socket and UDP disabled. A bounded, byte-transparent relay connects clients to that real native server. A preflight bind/drop would not protect the port and is rejected.

The provider has distinct persisted cache instances in schema 7, package references protected from cleanup, truthful process state, explicit start/stop/forget, and no implicit external-service adoption. Private socket directories are short, uniquely created and marked; cleanup removes only owned known files and never recursively removes unknown contents. Stop/crash/shutdown closes clients and the held listener and stops only the owned process. Cache values are volatile. The initial limits are 16 MiB, one native worker and 32 relay connections. An external endpoint remains independent and has no managed process.

`socket2 = =0.6.5` is a direct pinned dependency for its existing Windows Unix-socket, timeout and socket I/O support (already present transitively); the existing Windows bindings add WinSock. Native tests prove that both a synthetic `SO_REUSEADDR` contender and the raw native binary cannot steal the managed port. Native cache and real PHP tests cover set/get, independent instances, crash/retry, same-port restart, volatile data, startup cancellation and ownership-preserving shutdown.

The PHP memcached artifact uses a versioned ServBay PHP-Windows-Portable archive whose GitHub publisher asset supplies SHA256. This is third-party publisher integrity, not a missing PECL ZIP checksum or a claim of independent reproducible builds. Only the recorded memcached DLL and verified native dependency paths enter a project profile. The 8.5.11-built memcached 3.4.0 DLL loads on both official PHP 8.5.11 and 8.5.12. The 8.5.12-built DLL fails on 8.5.11 despite matching API numbers; actual load probes remain mandatory, and that reverse candidate preserves the active profile. Native DLL directories are process-local; global PATH and runtime installations remain untouched.

Live profile rollout validates a candidate before changing workers. It restarts only previously live PHP workers in the selected project, keeps observed ports and unrelated PIDs, and restores the prior immutable profile and workers on failed readiness. Failed recovery is reported explicitly. PHP-CGI uses bounded TCP readiness and the selected runtime's sibling executable; Apache owns the document root, rewrite and HTTP/HTTPS transport. Public release, newer upstream server coverage and all Mac checks remain separate gates.
